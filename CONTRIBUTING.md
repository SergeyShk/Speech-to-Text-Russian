# Участие в проекте

Баг-репорты, идеи и пул-реквесты приветствуются. Общаться в issues и пул-реквестах можно по-русски и по-английски.

## Сообщить об ошибке или предложить идею

Откройте [issue](https://github.com/SergeyShk/Speech-to-Text-Russian/issues/new/choose) по шаблону. Для ошибки нужны команда или код, параметры аудио (формат, длительность, частота дискретизации, число каналов), ожидаемый и фактический результат, версии stt-ru, Python и ОС; если можно, приложите короткий фрагмент записи. Для идеи - что вы хотите сделать с записями и почему текущих возможностей не хватает.

## Окружение разработки

Проект использует [uv](https://docs.astral.sh/uv/) для управления зависимостями и [ruff](https://docs.astral.sh/ruff/) для линтинга и форматирования. Требуется Python 3.11 или новее.

```bash
git clone https://github.com/SergeyShk/Speech-to-Text-Russian.git
cd Speech-to-Text-Russian

make deps                   # создать окружение и установить все зависимости
uv run pre-commit install   # хуки: линтеры на коммите, тесты на пуше
```

Полный список команд - `make help`.

## Проверки

Перед отправкой пул-реквеста должны проходить:

```bash
make lint        # ruff check --fix, ruff format, mypy
make test-cov    # pytest: тесты и примеры из докстрингов (doctest) с порогом покрытия
make docs-build  # mkdocs build --strict, если менялась документация
```

То же самое выполняет CI на Python 3.11-3.14 (Linux), а также на Windows и macOS для одной версии Python.

## Что ожидается в пул-реквесте

- **Одна тема - один пул-реквест.** Правки не по теме лучше вынести отдельно.
- **Тесты.** Новый код покрыт тестами в `tests/` (структура повторяет пакет), покрытие не ниже 90 %.
- **Документация.** Документация двуязычная - русская страница `docs/*.md` и английская `docs/*.en.md` рядом, тест `tests/test_docs.py` следит, чтобы у них совпадали разделы, якоря и ссылки. Примеры в докстрингах и документации показывают фактический вывод.
- **Совместимость.** Изменение команд, их параметров, Python API и форматов вывода - только с пояснением в описании пул-реквеста: оно попадёт в заметки релиза.
- **Стиль.** Код форматируется ruff (`make format`), типы проверяются mypy, докстринги на русском в принятом в проекте формате (`Описание`, `Аргументы`, `Вывод`, `Исключения`). Справка команд, сообщения и тексты интерфейса - тоже на русском, имена в коде - на английском. Комментарии в коде не дублируют то, что видно из него самого.
- **Коммиты.** Сообщения на русском в повелительном наклонении: «Добавить …», «Исправить …», «Убрать …».

Описание пул-реквеста отвечает на два вопроса: что сделано и почему. Если пул-реквест закрывает issue, укажите его номер.

## Как устроен репозиторий

- `src/stt_ru/` - пакет stt-ru.
- `tests/` - тесты, повторяющие структуру пакета; `tests/test_docs.py` сверяет два языка документации.
- `docs/` - документация MkDocs (Material), `mkdocs.yml` - навигация и перевод её на английский.
- `.github/workflows/` - CI (`ci.yml`), публикация (`publish.yml`), документация (`docs.yml`), Docker-образы (`docker.yml`: сборка и проверка в PR, публикация в GHCR при выпуске), ноутбуки (`notebooks.yml`, по расписанию и вручную).
- `docker/` - Docker-образы для CPU и NVIDIA GPU и файлы Docker Compose.
- `notebooks/` - ноутбуки с примерами; зависимости ставятся отдельно (`uv sync --all-extras --group notebooks`), после правок ноутбуки выполняются командой `make notebooks`, выводы хранятся в файлах, метаданные выполнения убирает nbstripout.

Версия хранится только в `pyproject.toml`; релизы выпускаются через GitHub Release, изменения описываются в его заметках, отдельного файла CHANGELOG нет.
